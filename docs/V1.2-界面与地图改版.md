# 午间岛 V1.2：早期微信风格 + 模拟对讲机 + OpenStreetMap 底图 + 首次隐私提示

> 产品目标（2026-11）：界面采用早期微信风格；地图不使用高德风格，也不复用既有地图应用的资料，改用全新数据源；
> 1v1 聊天的对讲按钮做成模拟对讲机，发送语音的按钮也换成对讲机上的按键；位置共享只在第一次使用时弹出隐私提醒，
> 确认进入即表示接受隐私协定，位置数据不保存、退出即删除。

## 2. 地图数据源选型

### 2.1 候选与比较

| 方案 | 数据 / 许可 | 用量限制 | 中国大陆可达性 | H5 / App | 小程序 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **自建 Protomaps PMTiles**（单文件矢量瓦片，HTTP Range 读取） | OSM，ODbL；样式 @protomaps/basemaps（BSD-3，设计 CC0） | 无（自己的服务器 / 对象存储） | ✅ 放在国内服务器 / 对象存储即可，**无境外依赖** | ✅ MapLibre + pmtiles 协议 | ❌（见 2.3） | **默认采用** |
| OpenFreeMap 公共实例 | OSM，ODbL；项目 MIT；OpenMapTiles 架构 | 官网：不限浏览量与请求数、无 key、可商用；离线下载每次 ≤3000 瓦片 / 50 MB；**无 SLA** | ⚠️ 服务器在境外（匈牙利），国内可能慢或不稳定，**本机在境外网络，未能实测** | ✅ MapLibre 直接用样式 URL | ❌ | 备选（`MAP_STYLE_URL`），开发 / 境外用户 |
| 自建 OpenMapTiles / OpenFreeMap 全套 | 同上 | 无 | ✅ | ✅ | ❌ | 需要大服务器，V1.2 不做 |
| OSM 官方瓦片 tile.openstreetmap.org | ODbL | 使用政策禁止重度 / 商业 App 依赖，要求可随时切换 | ⚠️ 境外 | 栅格 | ❌ | **不采用**（遵守 OSM Tile Usage Policy） |
| 天地图（国家地理信息公共服务平台） | 官方数据，**有审图号**；CGCS2000 ≈ WGS-84 | 需注册 key，有日调用限额 | ✅ 国内 | 栅格 / WMTS | ❌ | 合规更稳的“全新数据”选项，需自行注册 key（见 §5） |
| 高德 / 腾讯 | GCJ-02，有审图号 | key | ✅ | — | 腾讯 = 小程序自带 | 高德按要求不再使用；腾讯只在小程序原生 `<map>` 里使用 |

### 2.2 选择与理由

1. **默认：自带 PMTiles**（`backend/tiles/*.pmtiles`）。整份底图就是一个静态文件，后端 `/tiles` 直接提供（支持 Range），也可以放到国内对象存储 /
   CDN（设 `MAP_PMTILES_URL`）。这是唯一一个**不依赖境外服务、又不用高德**的方案，最符合“全新数据 + 国内可用”。
   字形（Noto Sans，OFL）也由 `/tiles/fonts` 提供；汉字用设备本机字体渲染（MapLibre `localIdeographFontFamily`），不用下载几十 MB 的 CJK 字形。
2. **备选：OpenFreeMap**。没有 PMTiles 文件时自动使用（`positron` 浅色样式，标注改中文优先）。
3. **都失败时**：前端退回“相对位置视图”（不加载任何底图，只显示双方相对位置与比例尺），**没有静默回退到高德**。
4. 演示文件：`backend/scripts/fetch-tiles.sh` 用 go-pmtiles 从 Protomaps 每日构建裁剪北京中心城区（116.25,39.85–116.50,40.00，最高 15 级，约 **11 MB**）。
   全国范围（73,18–135,54，15 级）预计数 GB，需放对象存储。PMTiles 文件体积大，**不入 git**（`.gitignore`），用脚本生成。

### 2.3 微信小程序的限制

小程序不能运行 MapLibre（没有 DOM / WebGL 画布的同等能力，`<web-view>` 需业务域名且体验差），原生 `<map>` 组件的数据源是**腾讯地图**，不能替换成 OSM 瓦片。
处理：小程序继续用原生 `<map>`；实时位置统一是 WGS-84，`live-map` 组件在显示前转成 GCJ-02（`utils/coords.js wgs84ToGcj02`），服务端把小程序上报的 GCJ-02 反解回 WGS-84。
如果一定要小程序也用 OSM，只能用 `<web-view>` 嵌 H5 地图页（需要已备案的业务域名），列为待定。

### 2.4 坐标系

OSM 数据是 WGS-84，与 GPS / 浏览器定位一致，**H5 / App 不再做 GCJ-02 偏移**。GCJ-02 转换只保留在小程序 `<map>` 这一处（以及服务端反解小程序上报）。

## 4. 位置共享隐私提示：只在第一次

| 项 | 设计 |
| --- | --- |
| 何时弹出 | 账号第一次开始位置共享；撤回后再次使用；`LOCATION_PRIVACY_VERSION` 提升后 |
| 弹窗内容 | 谁能看到 / 位置不保存 / 退出即删除（写明无时间限制） / 地图数据来源 / 随时撤回（`frontend/src/realtime/privacy-notice.js`，版本 2026-11-v2） |
| 同意方式 | 点“确认并开始共享”即视为同意（弹窗底部写明），客户端发 `loc.start { consent: true }` |
| 记录在哪 | **服务端，按账号**：`db.privacyConsents = [{ id, userId, kind: 'location_share', version, acceptedAt, platform, withdrawnAt }]`，不含任何位置；换设备 / 重装不再弹 |
| 之后 | `chat.state.locationConsent.accepted = true` → 客户端直接开始，服务端也不再要求 consent |
| 查看 / 撤回 | “我 → 隐私”；`GET /api/account/privacy/location`、`POST /api/account/privacy/location/withdraw`；撤回立即结束进行中的共享 |
| 数据导出 | `/api/account/export` 包含同意记录（位置不保存，所以没有可导出的位置） |
| 保留的控制 | 共享中醒目提示（聊天页横幅；V1.3 起地图页不再有底部条）、一键停止（地图页左上“退出共享”）；**无时长选项、无倒计时、无到期**（持续到停止或退出） |

## 5. 待决事项

1. **地图合规（审图号）**：在中国大陆公开发布的地图需经审核取得审图号；OSM 数据没有审图号，国界、地名等可能不符合要求。
   上架国内应用商店 / 小程序审核时有被要求整改的风险。选项：
   - A. 继续用 OSM（当前实现），只在城市街道级别使用、不显示国界，接受审核风险；
   - B. 改用**天地图**（官方数据、有审图号、也是“全新数据”，需注册 key 并配置为 MAP_STYLE_URL / 栅格源，需要少量代码）；
   - C. 改用腾讯地图 JS（与小程序同源，有审图号，需 key）。
2. **底图托管**：生产建议把全国（或业务城市）PMTiles 放到国内对象存储 + CDN，设 `MAP_PMTILES_URL`。全国 15 级约数 GB，存储 + 流量按云厂商计费，需自行开通。
3. 小程序是否需要 OSM 底图（只能 `<web-view>` + 备案业务域名），还是接受腾讯底图。
4. App 端实时对讲仍需原生音频插件（V1.1 遗留，见设计说明 §5）。
