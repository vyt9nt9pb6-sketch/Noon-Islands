## 2. 传输方案选择：WebSocket 中继（V1）

| 方案 | 微信小程序 | Android/iOS App（uni-app） | 鸿蒙 | 大陆网络 | 结论 |
| --- | --- | --- | --- | --- | --- |
| WebRTC P2P / SFU | ❌ 无 WebRTC（只有 live-pusher / 腾讯 TRTC，需额外类目资质与腾讯云账号） | 逻辑层无 WebRTC，需原生插件 | 需原生 | 需要自建 STUN/TURN，否则 NAT 穿透失败 | V1 不采用 |
| **WebSocket 中继压缩音频分片** | ✅ `uni.connectSocket` 支持二进制 | ✅（采集需原生插件） | ✅ | ✅ 只连自己的后端，无境外依赖 | **V1 采用** |

一条 WebSocket（`/ws`）同时承载：JSON 信令（话权、位置、在线状态）+ 二进制音频分片。

### 音频格式

- 采集 → 8 kHz 单声道 → **G.711 μ-law**（纯 JS，四端可用，无需 WASM）
- 每 40 ms 一帧：4 字节头（codec=1、序号 uint16、streamId）+ 320 字节负载
- 码率约 **64 kbps（≈ 8.7 KB/s 含帧头与 WS 开销）**；讲 1 分钟约 0.5 MB 上行 + 0.5 MB 下行
- 服务端只转发、不解码、不落盘

### 延迟估算（未在真实网络实测）

采集分帧 40 ms + 浏览器采集缓冲约 20 ms + 上行网络 + 服务端转发 + 下行网络 + 抖动缓冲 120 ms
≈ 国内同城 **250–400 ms**，跨省 / 4G 弱网更高。本机回环实测（Playwright 假麦克风）：1.5 秒按住 → 对方收到 30+ 帧，无丢帧。

## 3. 权限矩阵（服务端强制，客户端仅显示）

| 会话关系 | 文字 | 对讲 | 位置共享 |
| --- | --- | --- | --- |
| 同公司 | ✅ | ✅ | ✅ |
| 同集团跨公司（双方组织认证有效、已接受） | ✅ | ✅ | ✅ |
| 跨集团 · 双方均已组织认证 | ✅ | ✅ | ✅ |
| **跨集团 · 受限模式（任一方未认证）** | ✅ | ❌ **默认不允许** | ❌ **默认不允许** |
| 组织认证过期 / 离职（发送阻断） | ❌ | ❌ | ❌ |
| 任一方屏蔽对方 | ❌ | ❌ | ❌（进行中的共享立即结束） |
| 非会话成员 / 群聊 | — | ❌ | ❌ |

受限模式的理由：PRD 2.3 规定受限模式“仅文字”，语音与位置属于更敏感的能力（位置是 PIPL 敏感个人信息）。
开关在 `backend/src/services/flags.js` 的 `restrictedModeRealtime`（V1 为空数组 = 都不允许），
另有 `walkieTalkie` / `locationShare` 按平台关闭的开关。每条位置更新都会重新校验权限，权限变化立即结束共享。

## 4. 规则细节

### 对讲（话权控制）

- 按下 → `ptt.start`；服务端判定：权限 → 对方在线 → 话权空闲，否则返回 `peer_offline` / `busy`
- V1.3：聊天页进入对讲模式时隐藏整行文字输入栏（输入框 / 对讲机键 / “+”），对讲面板右上角“退出对讲”回到文字聊天
- 同一会话同一时刻只有一人能讲；对方讲话时对讲机 LED 变橙、PTT 键变灰（busy）。V1.2 追加后对讲机不再设液晶屏和 CH/MON/VOL 装饰键，保留天线、旋钮、网罩、LED、PTT
- V1.2 对讲机外观：发射 = 红灯 + 粉红背光，接收 = 橙灯 + 琥珀背光，连接中 = 红灯闪烁；按下 / 松开 / 对方开始讲话时 `uni.vibrateShort` 轻震
- 自动释放：松开、单次最长 **60 秒**、**3 秒**收不到音频（断网 / 卡死）、讲话方断线、对方离线
- 收听方：首次收到音频需要一次用户手势解锁播放（iOS / 浏览器自动播放策略）——按任意一次 PTT 即解锁，否则显示“轻点这里开启声音”
- 采集：V1.2 起 AudioContext 在按下手势内同步创建并 resume，再等待麦克风授权（iOS Safari 要求；也减少首次按下的丢帧）；打开对讲机面板 / 点“共享我的实时位置”时（也是用户手势）先预热 AudioContext（不申请麦克风，15 秒不用自动关闭）。e2e 首次按下从 5–23 帧提升到稳定 45 帧（3 次连跑）

### 位置共享

- **V1.2：隐私提示只在第一次使用时弹出**。点“确认并开始共享”即视为同意，客户端发 `consent: true`，服务端记录
  `{ userId, kind: location_share, version, acceptedAt }`（`services/consent.js`，**按账号保存在服务端**，换设备 / 重装不再弹）；
  之后的 `loc.start` 不需要再带 consent。未同意时服务端回 `loc.denied { code: consent_required }`，客户端据此弹出提示
- 可在“我 → 隐私”查看授权时间与版本、阅读全文、撤回（`POST /api/account/privacy/location/withdraw`，撤回即结束进行中的共享，下次重新弹提示）
- 提示内容有实质变更时提升 `LOCATION_PRIVACY_VERSION`，所有人会再看到一次
- 时长：V1.2 起**没有时间限制**，一直持续到用户点地图页左上角“退出共享”（或聊天页横幅“停止”）；不设 15 分钟 / 1 小时档，也不设 8 小时上限（单次对讲仍最长 60 秒，与本条无关）
- 醒目提示：聊天页顶部横幅“你正在共享实时位置 · 停止”；地图页 V1.3 起不再有底部提示条，左上角“退出共享”即停止（顶部我的头像绿框表示正在共享）
- 一键停止：客户端立即停止定位并通知服务端，对方地图上的标注立即消失
- 共享者断线 60 秒内重连可继续，否则自动结束
- 坐标（V1.2）：**统一 WGS-84** 转发（OpenStreetMap 底图就是 WGS-84，与 GPS 一致，无需偏移）。小程序上报 GCJ-02，服务端用 `gcj02ToWgs84` 反解；
  小程序原生 `<map>`（腾讯底图，GCJ-02）显示前在 `live-map` 组件里再转回 GCJ-02
- 退出即删除：地图页“退出共享”（V1.3 由原“退出”与“停止共享”合并）= 停止共享、删除位置并离开地图页；“收起”= 回到聊天、后台继续共享（聊天页顶部横幅可随时停止）
- 发送节流：首点立即发；之后移动 ≥5 米或 ≥10 秒才发，最快 2 秒一次；服务端再限 1 次/秒

### 隐私（不留历史）

- 位置只转发给会话对方；服务端内存只保留“最后一个点”，用于对方刚打开地图页时显示
- 共享结束（停止 / 退出共享页 / 断线 / 权限变化 / 撤回同意 / 退出登录 / 注销）立即从内存删除，不留任何坐标或轨迹
- **数据库不写任何坐标**；会话里只留一条无坐标的系统提示“X 开始/结束共享实时位置”，便于双方知情
- V1.2 已移除高德逆地理编码接口（`/api/geo/regeo`）与 `/_AMapService` 代理：地图不再使用高德的任何数据；“在 XX 路附近”改为只显示双方距离

## 6. 已知限制与生产化

| 限制 | 生产化建议 |
| --- | --- |
| μ-law 64 kbps，窄带音质 | 换 Opus（16–24 kbps，宽带音质）；App 用原生编码，H5 用 WASM 版 libopus（BSD-3-Clause） |
| 服务端中继，不是端到端加密（传输层 HTTPS/WSS 加密） | 上线必须 WSS；如需端到端加密要换 WebRTC + SFrame |
| 单进程内存状态，不能多实例横向扩展 | 话权与共享状态迁到 Redis，多实例之间用 Redis Pub/Sub 转发 |
| App 退到后台：iOS 会断开 WebSocket，位置与对讲停止 | 后台位置需 Always 权限并重新做合规评估（V1 刻意不做）；来讲话时推送需接入厂商推送 / APNs |
| App 端实时采集需原生插件 | 二选一：购买 DCloud 插件（见 §1）或自研 UTS 插件（Android `AudioRecord` / iOS `AVAudioEngine`） |
| 大并发语音 | 自建 LiveKit / mediasoup SFU + coturn（部署在国内云），App 与 H5 走 WebRTC，小程序继续走 WS 中继 |
| ScriptProcessor 已标记弃用 | 浏览器支持后改 AudioWorklet（iOS Safari 14.5+ 支持，但微信内置浏览器兼容性需测） |
